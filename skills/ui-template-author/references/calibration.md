# 校准：从参照产品实测到风格包

从参照产品（网站、应用、截图）提炼 token 与组件规格时的采集纪律。**校准结论错了会让整条 token 链
建立在错误观测上**——quiet-inset 0.4.0 的「侧栏项 400 / 分组标题 15px」就是抓错元素层级造成的，
两轮校准后才推翻。

## 1. 测量层级：先问「这个值属于谁」

同一个视觉规格至少有两个 DOM 层级，浏览器给出的 computed style 完全不同：

| 层级 | 典型元素 | 陷阱 |
| --- | --- | --- |
| 容器 | `<a>`、`<button>`、包装 `div` | 多数**不设字体**，继承 body（16px/400）——读到的是文档默认值，不是组件规格 |
| 叶子 | 容器内的文字 `span`/`div`（`children.length === 0`） | 真实排版值在此 |

规则：

- **文字规格**（字号、字重、行高、文字色）一律取叶子节点。
- **盒子规格**（高度、圆角、内边距、背景、边框、阴影）取组件根元素。
- 两个层级都采，并在结论里标明取自哪层——这是双源验证。

## 2. 结论必须自带测量说明

参照数据落进 patch / CHANGELOG / theme.css 注释时，写成：

```
值 + 元素角色 + 选择特征
例：侧栏项 13px/500（叶子文字 span，容器 <a> 高 28px）
```

只写「实测 400」而不写层级，后来的读者无法复验，也无法判断它是否可信。

## 3. 采样渠道与限制

- **静态页优先**：列表、表单、按钮、卡片等组件直接从页面 computed style 取值，稳定可重复。
- **交互态单列清单**：菜单、弹层、tooltip、命令面板需要触发；IAB 里键盘快捷键（Cmd+K）
  和菜单点击可能两次都打不开——失败不重试，记录到待补清单，别用猜测值填。
- **样式表不一定可读**：现代产品用运行时注入样式，`document.styleSheets` 里搜不到浮层阴影，
  只能在打开态直接读元素 computed style；拿到截断值时保留截断标记并说明补全依据。
- **颜色空间先换算**：参照可能用 `lch()`/`hsl()`，契约只认 `oklch()`（校验器 T04）；换算口径
  见 `validate_package.py` 头注释（对比度在线性 sRGB 直接加权，不做 WCAG gamma 往返）。

## 4. 判定：校准结论 vs 已知偏差

- 能一致就一致（token 直接采用实测值）。
- 契约（对比度、必需 token 集合）与实测冲突时**保持契约**，把实测值与原因写进 theme.css 头注释
  「已知偏差」（参照 F-1 格式）。
- 尺寸类声明（density 注释里的 `controls 28px` 等）必须与 token 和组件读取链一致——`validate_package.py`
  的 P12 闸门会检查，声明了没兑现会被 warn。

## 4.5 组件形态也要采（不只 token）

2026-11 的两轮返工证明：只采颜色/字号/圆角 token 不够，**组件级形态**必须逐项实测对照，
否则模板会带着上游 shadcn 默认值出厂：

| 对象 | 采什么 |
| --- | --- |
| 控件 | 高度（input 28 / combobox 30 / 按钮 28/32）、圆角（控件 8 / 输入卡 10 / 面板 12）、字号 |
| 按钮 | 形态（参照产品多为 pill）、图标+文字取舍、各变体高度 |
| 开关/复选 | 尺寸（如 30×20）、轨道圆角、选中色 |
| 菜单/导航 | 行高（28）、hover 与选中分档（两档面层）、行间隔（2px）、容器 padding（p-1） |
| 命令面板 | 面板圆角/阴影、菜单项高度/字号 |
| 弹层 | 容器 padding（Dialog p-4 / Sheet p-4）、边框与阴影 |
| 链接 | hover 表达（颜色变化，不用下划线） |

采到的形态登记进 `contract/components.json`（P14 闸门守住），避免下次改模板时退化。

## 5. 采样完成后的交叉验证

1. 用 `map-tokens.mjs` 或自验脚本复算对比度等派生量（同口径）。
2. 反向验证：改动值后故意构造一次违规（如把 token 改错），确认校验器/闸门能报出来。
3. 组件 TOKEN 化时默认值等于现状，参照包显式置值——避免误伤其他参照包。
