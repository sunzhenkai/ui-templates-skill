# Workbench Shell 前端测试提示词：软件交付与运维事件协作中心

请实现一个用于测试 `workbench-shell` 模板的前端站点，业务方向为“软件交付与运维事件协作中心”。站点用于团队接收告警、创建和处理事件、跟踪服务健康、安排值班、查看交付指标以及管理工作区配置。

## 一、本提示词的边界

- 本文件**只描述功能、数据、状态流转和验收**，不描述页面布局。
- 导航形态、分区位置、组件类型、控件形态、断点行为、间距与配色一律以 `workbench-shell` 模板为唯一来源；本文件不列举需要哪些组件，也不指定任何元素放在页面的哪个位置。
- 本文件出现“入口”“操作”“字段”“状态”等词时，指的是功能可达，不指定其承载形态。
- 所有数据使用本地 mock，不需要真实后端，但交互结果必须在前端可见并保持一致。

## 二、功能范围

实现一个可运行的单页前端应用，覆盖以下工作区：

1. 收件箱
2. 事件列表
3. 事件看板
4. 服务目录
5. 值班安排
6. 交付分析
7. 工作区设置

应用需要支持以下通用能力：

- 在各工作区之间切换，并可回到应用起点。
- 在页面之间保留必要的筛选条件、选中项和已修改数据。
- 使用本地 mock 数据覆盖加载、成功、空数据和失败四类状态。
- 支持键盘操作、焦点移动和必要的 ARIA 标签。
- 页面刷新后恢复一个合理的默认工作区和默认路由；如果实现了本地持久化，可同时恢复用户最后一次选择。

## 三、全局功能

### 1. 工作区与全局入口

- 可切换到其他工作区，并展示当前所处工作区。
- 工作区切换后刷新可见的数据上下文，同时应用仍停留在当前功能区。
- 提供全局搜索入口，支持快捷键 `⌘K`（Windows/Linux 为 `Ctrl+K`）。
- 提供“创建事件”入口，支持快捷键 `C`；当前焦点位于输入框、文本域或可编辑控件内时不触发快捷键。
- 未读告警数量与待处理数量必须可被感知；数量为零时不占用注意力。
- 导航内容按语义分组：个人区（收件箱）、运维区（事件、服务、值班、分析）、配置区（设置）。
- 支持置顶事项与取消置顶。
- 无论导航处于何种状态，帮助入口都必须可达。

### 2. 全局搜索

- 可搜索事件、服务、团队成员和变更记录。
- 输入关键字后给出匹配结果分类、结果数量和无结果状态。
- 支持键盘上下选择结果、Enter 打开结果、Esc 退出搜索。
- 结果可按类型筛选；选中结果后跳转到对应功能并自动打开对应详情。
- 搜索过程显示加载状态；模拟失败时给出错误状态和重试操作。

### 3. 创建事件

- 可从任意位置发起创建事件。
- 表单字段包括：标题、影响服务、严重等级、当前状态、负责人、参与团队、发生时间、描述、标签、关联变更和附件。
- 标题、影响服务、严重等级为必填字段。
- 支持字段校验、错误提示、清空、取消和提交。
- 提交成功后生成新的事件编号，结束创建流程，并更新事件列表、看板、收件箱计数和相关服务统计。
- 提交失败时保留用户输入，并提供重试。
- 可从现有服务、成员和变更记录中选择；没有匹配项时给出空结果。

### 4. 操作反馈与确认

- 操作成功给出可感知反馈；操作失败给出错误反馈，并可重试。
- 危险操作必须先经确认。
- 需要补充上下文的操作必须有可达入口，其承载形态由模板决定。
- 提供可用快捷键清单，随时可查。
- 每个异步区域都必须可辨识地处于加载、成功、空或失败之一。

## 四、各工作区功能

### 1. 收件箱

用于集中处理新告警、被分派事件和需要用户确认的事项。

- 展示事项总量与未处理数量，并提供批量操作入口。
- 提供筛选条件：事项类型、严重等级、来源、负责人、时间范围和处理状态。
- 支持关键字搜索、重置筛选和保存筛选条件。
- 事项集合字段至少包括：编号、标题、类型、严重等级、来源、负责人、创建时间、处理状态。
- 支持单选、多选、全选当前结果，以及批量标记已读、批量分派负责人、批量关闭和批量加入事件。
- 选中单个事项可查看其详情，并在详情中执行确认、分派、标记已读、转为事件和关闭。
- 支持分页、每页条数切换和跳转页码。
- 覆盖无数据、加载失败和数据加载中三种状态。
- 事项详情支持上一条、下一条切换，切换后不丢失当前筛选条件。

### 2. 事件列表

用于查询和维护所有运维事件。

- 提供新建事件、导出当前结果和刷新数据。
- 支持筛选：事件状态、严重等级、影响服务、负责人、创建人、标签、时间范围。
- 支持组合筛选，并展示当前已生效的条件，可单独移除某个条件。
- 支持按字段排序、选择需要查看的字段，并在当前浏览器中保存该偏好。
- 事件字段至少包含：事件编号、标题、状态、严重等级、影响服务、负责人、开始时间、解决时间、更新时间。
- 支持选中后批量处理：分派、修改状态、添加标签、归档、删除。
- 删除和归档需要确认；批量操作完成后更新结果和统计数量。
- 事件可进入事件详情；负责人和影响服务可跳转到对应实体详情。
- 支持分页、每页条数、空数据、错误重试和加载状态。
- 支持把当前查询条件表达为可分享的 URL 参数；打开带参数的 URL 时恢复筛选条件。

### 3. 事件看板

用于按处理进度跟踪事件。

- 提供范围切换：我的事件、我的团队、全部事件。
- 按状态分组，分组至少覆盖：待确认、处理中、等待外部、已解决、已归档。
- 每个分组显示其事件数量。
- 每个事件条目显示编号、标题、严重等级、影响服务、负责人、最近更新时间和评论数量。
- 支持以拖拽或等效方式变更事件状态；变更前后同步事件列表、详情和收件箱数据。
- 状态变更失败时恢复原状态并给出错误反馈。
- 支持在指定状态分组内直接创建事件，并预置目标状态。
- 事件条目支持快捷操作：打开详情、分派负责人、添加标签、复制编号、归档。
- 支持按严重等级、服务和负责人过滤看板内容；过滤后给出每个分组的命中数量，无命中时给出空状态。

### 4. 事件详情

用于查看事件时间线并执行完整处理流程。

- 可访问事件编号、标题、当前状态和主要操作，并有明确的返回上一级路径。
- 详情内容包含：事件摘要、影响范围、严重等级、负责人、参与团队、关联服务、关联变更、标签、时间信息和附件。
- 支持状态流转：确认、开始处理、等待外部、标记解决、重新打开、归档。
- 不允许执行不符合当前状态的操作；不可用操作需说明原因或不予提供。
- 记录所有状态变化、负责人变化、字段修改和评论，形成时间线。
- 支持添加评论、提及成员、上传附件、编辑和删除自己的评论。
- 支持添加或移除标签、变更负责人、关联或取消关联变更记录。
- 可查看受影响服务的当前健康状态，并跳转到该服务详情。
- 提供上下文信息：相似事件、最近变更和相关告警。
- 覆盖加载失败、事件不存在（404）、无时间线数据和附件上传失败状态。
- 离开前若评论或字段存在未提交修改，需提示用户确认。

### 5. 服务目录

用于维护系统中的服务和服务依赖关系。

- 支持在明细浏览与概览浏览之间切换。
- 服务字段包含：名称、所属团队、负责人、当前健康状态、最近事件数、最近变更时间和更新时间。
- 支持按健康状态、团队、环境和关键字筛选。
- 支持按名称、事件数量和更新时间排序。
- 服务详情展示：基本信息、负责人、所属团队、运行环境、依赖服务、被依赖服务、最近事件、最近变更和健康检查记录。
- 支持新建服务、编辑服务、停用服务和恢复服务。
- 新建与编辑字段包括：名称、标识、描述、所属团队、负责人、环境、仓库地址、文档地址、依赖服务和告警规则。
- 服务标识必须唯一；重复时阻止提交并显示错误。
- 依赖关系支持搜索并选择多个服务；保存后关系变化立即可见。
- 停用服务需要确认；停用后不允许创建新的关联事件，但历史事件仍可查看。
- 覆盖服务详情加载失败、服务不存在、无事件、无依赖关系和健康检查失败状态。

### 6. 值班安排

用于安排团队值班和处理交接。

- 支持按月、周、日三种时间范围浏览排班。
- 支持切换上一个和下一个周期，并回到当前时间。
- 每个时段展示值班人员、值班班次和该时段内的事件数量。
- 选中时段可查看当天详情，选中班次可查看班次详情。
- 支持创建、编辑、复制和删除值班班次。
- 班次字段包括：团队、值班人员、开始时间、结束时间、交接对象、备注。
- 校验结束时间不得早于开始时间；同一团队班次重叠时给出冲突并阻止提交，除非用户明确选择强制保存。
- 支持调整班次时间；保存前展示变更结果，失败时恢复原数据。
- 支持按团队和人员过滤。
- 可从班次详情查看该班次负责期间的事件列表。
- 覆盖无排班、加载中、加载失败和时段内无事件状态。

### 7. 交付分析

用于查看事件处理效率、服务稳定性和交付变更情况。

- 提供时间范围切换：最近 7 天、最近 30 天、本季度、自定义范围。
- 提供团队、服务、环境和严重等级筛选。
- 展示指标：事件总数、未解决事件、平均响应时间、平均恢复时间、变更失败率、受影响服务数。
- 指标支持与上一周期比较，并可下钻到对应的过滤结果列表。
- 提供趋势与分布数据：事件数量趋势、响应和恢复时间趋势、按严重等级分布、按服务分布。
- 提供排行：事件最多的服务、响应最慢的团队、变更失败最多的服务。
- 所有图表与排行中的数据点都必须可被读出具体数值，其可视化形态由模板决定。
- 支持导出当前分析结果；导出使用 mock 下载文件即可。
- 支持从任意数据点或排行项跳转到事件列表，并自动带上对应筛选条件。

### 8. 工作区设置

用于维护工作区、团队、成员、通知规则和集成配置。

- 设置按以下分区组织：基本信息、成员与权限、团队、通知规则、集成、个人偏好。
- 基本信息支持编辑工作区名称、描述、默认时区和默认事件状态。
- 成员与权限支持成员列表、角色筛选、邀请成员、修改角色、暂停成员和移除成员。
- 邀请成员支持填写邮箱、角色和所属团队；邮箱格式错误时不能提交。
- 团队支持新建、编辑、停用，并管理团队成员和负责服务。
- 通知规则支持创建、编辑、启用、停用和删除；规则字段包括触发事件、严重等级、接收对象、通知渠道和静默时间。
- 集成支持新增 Webhook、测试连接、启用、停用和删除；测试连接给出成功或失败结果，但不需要真实发出请求。
- 个人偏好支持默认首页、时区、通知开关和快捷键开关。
- 所有设置表单都支持保存中、保存成功、保存失败、取消和未保存修改提醒。
- 危险操作必须二次确认，并在确认后更新相关数据。

## 五、数据与状态要求

- 为每个工作区准备足够的 mock 数据，使分页、筛选、排序、详情、统计和空状态都能被验证。
- 至少准备两类工作区、多个团队、多个成员、多个服务、多个事件、多个变更记录和多个值班班次。
- mock 数据应包含不同状态、严重等级、负责人、时间范围和关联关系。
- 提供可控的模拟延迟，使加载状态能被观察到。
- 提供一种可触发的模拟失败方式，例如在开发模式下使用固定关键字或开关触发请求失败，以便验证错误状态和重试。
- 所有新增、编辑、删除、状态切换、分派、评论、标签和设置变更都应更新前端状态；刷新前至少在当前会话中保持一致。
- 异步行为可用任意本地实现方式模拟，不依赖真实 API，也不在本文件中指定状态管理或数据请求方案。
- 表单数据必须有明确的类型定义和校验规则；提交无效数据时不能修改已有数据。

## 六、验收要求

每个主要功能至少验证以下状态：

- 初始加载状态。
- 正常数据状态。
- 空数据状态。
- 加载失败状态。
- 详情不存在状态。
- 操作提交中状态。
- 操作成功后的反馈状态。
- 操作失败后的恢复或重试状态。

同时满足：

- 所有可执行操作可通过键盘访问；进入浮层时焦点进入浮层，退出后焦点回到触发点。
- 表单控件具有关联标签；仅有图标的操作有可读的 `aria-label`。
- 状态信息不只依赖颜色传达，状态名称或等效辅助文本必须可见或可读。
- 不使用真实账号、真实邮箱、真实 API 密钥或外部服务凭据。

## 七、交付要求

- 产出完整的前端功能、必要的本地 mock 数据、状态流转和路由。
- 保持现有项目的技术栈和启动方式，不新增不必要的构建工具。
- 为关键流程提供可执行的测试或验收路径，至少覆盖：创建事件、筛选事件、变更事件状态、编辑事件评论、创建值班冲突、修改设置、处理空状态和重试失败请求。
- 确保项目可以通过现有的构建、lint、单元测试和 E2E 测试命令。
- 不要把需求简化为单一页面；必须实现上述多个工作区、工作区间跳转和跨工作区状态同步。
