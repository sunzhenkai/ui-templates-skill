# Workbench Shell 前端测试提示词：软件交付与运维事件协作中心

请实现一个用于测试 `workbench-shell` 模板的前端站点，业务方向为“软件交付与运维事件协作中心”。站点用于团队接收告警、创建和处理事件、跟踪服务健康、安排值班、查看交付指标以及管理工作区配置。

本任务只要求实现功能、页面结构、交互和状态流转，不要求设计或复刻任何特定视觉风格。请使用本仓库中的 `workbench-shell` 模板作为页面布局与交互约束来源；不要自行引入另一套 App Shell 规则。所有数据使用本地 mock 数据，不需要真实后端，但交互结果必须在前端可见并保持一致。

## 一、实现范围

实现一个可运行的单页前端应用，包含以下工作区：

1. 收件箱
2. 事件列表
3. 事件看板
4. 服务目录
5. 值班日历
6. 交付分析
7. 工作区设置

应用需要支持以下通用能力：

- 在不同工作区之间切换。
- 通过侧栏导航切换路由或页面状态。
- 在页面之间保留必要的筛选条件、选中项和已修改数据。
- 使用本地 mock 数据模拟加载、成功、空数据和失败状态。
- 在桌面宽度、平板宽度和移动宽度下保持可操作。
- 支持键盘操作、焦点移动和必要的 ARIA 标签。
- 页面刷新后恢复一个合理的默认工作区和默认路由；如果实现了本地持久化，可同时恢复用户最后一次选择。

## 二、应用外壳与全局功能

按 `workbench-shell` 模板实现统一的 App Shell，功能要求如下：

### 1. 侧栏

- 顶部提供工作区切换器，展示当前工作区名称和工作区列表。
- 工作区切换后，刷新当前页面可见的数据上下文，并保留应用仍位于当前功能区。
- 提供全局搜索入口，点击后打开搜索面板；支持快捷键 `⌘K`，Windows/Linux 环境支持 `Ctrl+K`。
- 提供“创建事件”入口，支持快捷键 `C`；如果当前焦点位于输入框、文本域或可编辑控件内，不应触发快捷键。
- 导航项显示未读告警数量或待处理数量；数量为零时不显示徽标。
- 导航分为个人区、运维区和配置区；个人区包含收件箱，运维区包含事件、服务、值班和分析，配置区包含设置。
- 支持折叠“置顶事件”分组；置顶事件可从列表中取消置顶。
- 侧栏内容过多时，只有导航内容区域滚动，底部帮助入口保持可访问。
- 支持在宽屏下调整侧栏宽度；拖动结束后保留新宽度，刷新页面可恢复。
- 在窄屏下侧栏改为可打开和关闭的抽屉；点击导航后自动关闭。

### 2. 全局搜索

- 搜索面板支持搜索事件、服务、团队成员和变更记录。
- 输入关键字后显示匹配结果分类、结果数量和无结果状态。
- 支持键盘上下选择结果、Enter 打开结果、Esc 关闭面板。
- 结果可按类型筛选；选择结果后跳转到对应页面，并自动打开对应详情。
- 搜索过程中显示加载状态；模拟失败时显示错误状态和重试操作。

### 3. 全局创建事件

- 从任意页面打开创建事件弹窗或页面。
- 表单字段包括：标题、影响服务、严重等级、当前状态、负责人、参与团队、发生时间、描述、标签、关联变更和附件。
- 标题、影响服务、严重等级为必填字段。
- 支持字段校验、错误提示、清空、取消和提交。
- 提交成功后生成新的事件编号，关闭创建流程，更新事件列表、看板、收件箱计数和相关服务统计。
- 提交失败时保留用户输入，并提供重试操作。
- 支持从创建表单中选择已有服务、成员和变更记录；没有匹配项时显示空结果。

### 4. 全局反馈与浮层

- 页面操作成功后显示 toast；失败操作显示错误 toast，并提供可选的重试入口。
- 危险操作必须先通过确认对话框确认。
- 需要补充上下文的操作使用弹出菜单、下拉选择、工具提示或侧滑详情面板。
- 支持全局快捷键帮助面板，列出当前可用快捷键。
- 路由或页面数据切换时显示加载反馈；禁止用无穷旋转作为唯一加载反馈，列表和卡片区域应提供骨架状态。

## 三、路由与页面功能

### 1. 收件箱

用于集中处理新告警、被分派事件和需要用户确认的事项。

- 页面顶部显示标题、未处理数量和批量操作入口。
- 提供筛选条件：事项类型、严重等级、来源、负责人、时间范围和处理状态。
- 支持关键字搜索、重置筛选和保存筛选条件。
- 主区域以列表展示事项，列表字段至少包括：编号、标题、类型、严重等级、来源、负责人、创建时间、处理状态。
- 支持单选、多选、全选当前结果和批量标记已读。
- 支持批量分派负责人、批量关闭和批量加入事件。
- 点击列表行打开详情面板；详情面板中可执行确认、分派、标记已读、转为事件和关闭操作。
- 支持列表分页、每页条数切换和跳转页码。
- 模拟无数据、加载失败和数据加载中的状态。
- 事项详情支持上一条、下一条切换，切换后不丢失当前列表筛选。

### 2. 事件列表

用于查询和维护所有运维事件。

- 页面提供新建事件、导出当前结果和刷新数据操作。
- 支持以下筛选：事件状态、严重等级、影响服务、负责人、创建人、标签、时间范围。
- 支持组合筛选条件，并展示当前已生效的筛选条件；可单独移除某个条件。
- 支持表格列排序、列显示/隐藏和列宽调整；列配置可在当前浏览器中保存。
- 表格至少包含：事件编号、标题、状态、严重等级、影响服务、负责人、开始时间、解决时间、更新时间。
- 支持行选择和批量操作：分派、修改状态、添加标签、归档、删除。
- 删除和归档需要确认；批量操作完成后更新表格和统计数量。
- 点击事件编号或标题进入事件详情页；点击负责人和服务名称可进入对应实体详情。
- 支持分页、每页条数、空数据、错误重试和骨架加载。
- 支持将当前查询条件复制为可分享的 URL 参数；打开带参数的 URL 时恢复筛选条件。

### 3. 事件看板

用于以状态列跟踪事件处理流程。

- 提供范围切换：我的事件、我的团队、全部事件。
- 看板列至少包括：待确认、处理中、等待外部、已解决、已归档。
- 每列显示事件数量，并支持列内滚动。
- 事件卡片显示编号、标题、严重等级、影响服务、负责人、最近更新时间和评论数量。
- 支持拖动事件卡片变更状态；状态变更前后更新事件列表、详情页和收件箱数据。
- 拖动失败时恢复原位置并显示错误反馈。
- 支持从列头创建事件，创建时自动填入目标状态。
- 支持卡片快捷菜单：打开详情、分派负责人、添加标签、复制编号、归档。
- 支持按严重等级、服务和负责人过滤看板内容。
- 过滤后显示每列过滤结果数量；没有匹配项时显示列内空状态。
- 在移动宽度下支持按列切换查看，不要求同时展示所有列，但所有列和事件仍必须可访问。

### 4. 事件详情

用于查看事件时间线并执行完整处理流程。

- 页面顶部显示返回入口、事件编号、标题、当前状态和主要操作。
- 支持面包屑从事件详情返回事件列表或看板。
- 详情内容包括：事件摘要、影响范围、严重等级、负责人、参与团队、关联服务、关联变更、标签、时间信息和附件。
- 提供状态流转操作：确认、开始处理、等待外部、标记解决、重新打开、归档。
- 不允许执行不符合当前状态的状态操作；不可用操作需要说明原因或不展示。
- 记录所有状态变化、负责人变化、字段修改和评论，形成时间线。
- 支持添加评论、@成员、上传附件、删除自己的评论和编辑自己的评论。
- 支持添加/移除标签、变更负责人、关联/取消关联变更记录。
- 支持查看受影响服务的当前健康状态，并可跳转服务详情。
- 支持右侧上下文面板，展示相似事件、最近变更和相关告警。
- 支持加载失败、事件不存在（404）、无时间线数据和附件上传失败状态。
- 离开页面前如果评论或字段存在未提交修改，提示用户确认离开。

### 5. 服务目录

用于维护系统中的服务和服务依赖关系。

- 页面支持列表视图和聚合卡片视图切换。
- 列表视图展示服务名称、所属团队、负责人、当前健康状态、最近事件数、最近变更时间和更新时间。
- 支持按健康状态、团队、环境和关键字筛选。
- 支持按名称、事件数量和更新时间排序。
- 点击服务打开服务详情；服务详情展示基本信息、负责人、所属团队、运行环境、依赖服务、被依赖服务、最近事件、最近变更和健康检查记录。
- 支持新建服务、编辑服务、停用服务和恢复服务。
- 新建/编辑表单字段包括：名称、标识、描述、所属团队、负责人、环境、仓库地址、文档地址、依赖服务和告警规则。
- 服务标识必须唯一；重复时阻止提交并显示错误。
- 支持在依赖关系中搜索并选择多个服务；保存后在关系图或关系列表中反映变化。
- 停用服务需要确认；停用后不允许创建新的关联事件，但历史事件仍可查看。
- 支持服务详情加载失败、服务不存在、无事件、无依赖关系和健康检查失败状态。

### 6. 值班日历

用于安排团队值班和处理交接。

- 支持月视图、周视图和日视图切换。
- 支持切换上一个/下一个周期和回到今天。
- 日历中展示值班人员、值班班次和该时段发生的事件数量。
- 点击日期打开当天详情；点击班次打开值班详情。
- 支持创建、编辑、复制和删除值班班次。
- 班次字段包括：团队、值班人员、开始时间、结束时间、交接对象、备注。
- 校验结束时间不得早于开始时间；同一团队的班次重叠时显示冲突并阻止提交，除非用户明确选择强制保存。
- 支持拖动或调整班次时间；保存前展示变更结果，失败时恢复原数据。
- 支持按团队和人员过滤。
- 支持从值班详情直接查看该班次负责期间的事件列表。
- 移动宽度下提供可切换的日期列表和当天详情，不要求使用完整月历网格。
- 支持无排班、加载中、加载失败和日期无事件状态。

### 7. 交付分析

用于查看事件处理效率、服务稳定性和交付变更情况。

- 提供时间范围切换：最近 7 天、最近 30 天、本季度、自定义范围。
- 提供团队、服务、环境和严重等级筛选。
- 页面显示以下指标：事件总数、未解决事件、平均响应时间、平均恢复时间、变更失败率、受影响服务数。
- 指标支持与上一周期比较，并能点击指标进入对应的过滤结果列表。
- 提供趋势图：事件数量趋势、响应/恢复时间趋势、按严重等级分布、按服务分布。
- 提供排行列表：事件最多的服务、响应最慢的团队、变更失败最多的服务。
- 图表支持悬停查看数据、图例开关、无数据状态和数据加载失败重试。
- 支持导出当前分析结果；导出操作使用 mock 下载文件即可。
- 支持从图表数据点或排行项跳转到事件列表，并自动带上对应筛选条件。
- 在窄屏下图表应转为可横向查看或分组展示，数据不能被隐藏。

### 8. 工作区设置

用于维护工作区、团队、成员、通知规则和集成配置。

- 设置页面包含以下子页面或标签：基本信息、成员与权限、团队、通知规则、集成、个人偏好。
- 基本信息支持编辑工作区名称、描述、默认时区和默认事件状态。
- 成员与权限支持成员列表、角色筛选、邀请成员、修改角色、暂停成员和移除成员。
- 邀请成员表单支持邮箱、角色和所属团队；邮箱格式错误时不能提交。
- 团队页面支持新建、编辑、停用团队，并管理团队成员和负责服务。
- 通知规则支持创建、编辑、启用/停用和删除规则；规则字段包括触发事件、严重等级、接收对象、通知渠道和静默时间。
- 集成页面展示集成列表，支持新增 Webhook、测试连接、启用/停用和删除；测试连接显示成功或失败结果，但不需要真实发出请求。
- 个人偏好支持默认首页、时区、通知开关和快捷键开关。
- 所有设置表单都支持保存中、保存成功、保存失败、取消和未保存修改提醒。
- 危险操作必须二次确认，并在确认后更新相关列表。

- 列表、数据表格、可排序表头、分页器、列配置器、虚拟或内部滚动容器。
- 看板列、可拖动卡片、拖动状态反馈。
- 卡片、指标卡、统计摘要、列表行、头像、状态徽标、标签、未读计数。
- 文本输入、搜索输入、文本域、数字输入、日期选择器、日期范围选择器、时间选择器。
- 单选、多选、复选框、开关、滑块、下拉选择、组合框、可创建选项的选择器。
- 按钮、图标按钮、链接、键盘快捷键提示、工具提示、弹出菜单、命令面板。
- 对话框、确认对话框、侧滑面板、嵌套弹层、表单校验和未保存修改提示。
- 文件上传、附件列表、上传进度、上传失败重试。
- 时间线、活动记录、评论编辑器、@成员选择。
- 日历的月/周/日视图和班次编辑。
- 趋势图、分布图、排行列表、图表图例和数据详情。
- Toast、错误提示、空状态、404 状态、骨架加载、重试操作。
- 响应式导航、移动端抽屉、移动端底部或顶部操作区、横向滚动内容。

## 五、数据与状态要求

- 为每个功能区准备足够的 mock 数据，使列表、分页、筛选、排序、详情、统计和空状态都能被验证。
- 至少准备两类工作区、多个团队、多个成员、多个服务、多个事件、多个变更记录和多个值班班次。
- mock 数据应包含不同状态、严重等级、负责人、时间范围和关联关系。
- 提供可控的模拟延迟，让加载状态能被观察到。
- 提供一种可触发的模拟失败方式，例如在开发模式下使用固定关键字或开关触发请求失败，以便验证错误状态和重试。
- 所有新增、编辑、删除、状态切换、分派、评论、标签和设置变更都应更新前端状态；刷新前至少在当前会话中保持一致。
- 需要异步请求行为的地方可使用本地 Promise、TanStack Query 或等效方案，但不要依赖真实 API。
- 表单数据必须有明确的类型定义和校验规则；提交无效数据时不能修改已有数据。

## 六、页面状态与可访问性验收

每个主要页面至少验证以下状态：

- 初始加载状态。
- 正常数据状态。
- 空数据状态。
- 加载失败状态。
- 详情不存在状态。
- 操作提交中状态。
- 操作成功后的反馈状态。
- 操作失败后的恢复或重试状态。

同时满足：

- 所有可点击操作可通过键盘访问；弹层打开时焦点进入弹层，关闭后焦点回到触发控件。
- 表单控件具有关联标签；图标按钮有可读的 `aria-label`。
- 状态颜色不是传达状态的唯一方式，状态名称或辅助文本必须可见或可读。
- 表格、看板、日历和图表在窄屏下仍可完成核心操作。
- 不使用真实账号、真实邮箱、真实 API 密钥或外部服务凭据。

## 七、交付与验收

- 产出完整的前端页面和必要的本地 mock 数据、状态管理、路由和组件。
- 保持现有项目的技术栈和启动方式，不新增不必要的构建工具。
- 为关键流程提供可执行的测试或验收路径，至少覆盖：创建事件、筛选事件、拖动事件变更状态、编辑事件评论、创建值班冲突、修改设置、处理空状态和重试失败请求。
- 确保项目可以通过现有的构建、lint、单元测试和 E2E 测试命令。
- 不要把需求简化为单一仪表盘；必须实现上述多个页面、页面间跳转和跨页面状态同步。
