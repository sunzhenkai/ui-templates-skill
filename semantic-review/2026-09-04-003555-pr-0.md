# 分析钻取、通知偏好与看板 URL 的最终 P1 复审

本轮把分析钻取统一到集中 query builder，事件列表开始实际消费时间、环境、团队、服务、等级和指标语义，同时补上上一等长周期、delta、失败变更服务排行及同源导出。个人通知偏好现在由草稿写入持久 store，并在 Shell 中呈现独立于操作 Toast 的模拟后台摘要状态；看板的 `scope` 和 `column` 也改为白名单解析和 replace 规范化。主路径与文档声明基本一致，但分析页仍会把“仅有成功变更、没有事件”的有效窗口误判为空。Watch for: **confirmed** — `changeFailureRate = 0%` 的有效结果会被页面空态遮蔽，应让数据门禁识别所有相关变更并补回归测试。

**Verdict**: NEEDS_CHANGES

## High-level view

分析钻取由 `buildAnalyticsIncidentQuery` 统一构造，非自定义范围也会物化为明确的 `from/to`，事件列表按同一时间边界、服务环境和指标样本过滤。失败变更率不再生成空 `change=`，而是留在分析页的专用明细与按服务钻取中，返回来源保留完整分析 URL。

派生层用当前窗口长度构造紧邻的上一周期，并对六个指标生成差值；失败变更按 `serviceId` 聚合，页面和 JSON 导出共同消费 `deriveAnalytics` 的结果。唯一阻断项是 **confirmed**：页面门禁只检查事件和失败变更，因此仅有成功变更时，派生出的 0% 失败率和上一周期对比不会显示。

通知开关读写 `draft.notifications`，保存后进入 Zustand persist；Shell 直接订阅持久偏好并显示后台摘要开关状态。通知规则与外部发送继续明确为不可用 mock，成功/错误 Toast 不读取该偏好。

看板把 `scope` 限制为 `all|mine|team`、把 `column` 限制为 `INCIDENT_STATUSES`，非法值和显式默认值通过 replace 从 URL 移除。移动视图按规范化列渲染，空筛选结果可清除并回到默认 URL。

## 成功变更被空态门禁丢弃

**confirmed** — `deriveAnalytics` 会把当前窗口内的全部相关变更交给 `calculateMetrics`，所以窗口内只有成功变更时会正确产生 `changeFailureRate: 0`；但 `AnalyticsPage` 的 `hasData` 只判断 `analytics.filtered.length > 0 || analytics.failedChanges.length > 0`。在没有事件、没有失败变更但存在成功变更的窗口中，页面转入“当前分析范围没有数据”，六个指标、delta 和导出入口全部被隐藏。应让派生结果暴露相关变更数量或显式 `hasData`，并增加“零事件 + 至少一个成功变更”的单测和页面级测试；`docs/verification.md` 的“当前没有已知未解决 P0/P1”声明需在该行为闭环后才成立。

## 集中 query 与事件样本语义

`buildAnalyticsIncidentQuery` 保留 `range/from/to/team/service/environment/severity`，再叠加 `metric`；指标、趋势链接、严重等级分布、服务分布及事件/团队排行都通过该入口生成目的 URL。`IncidentListPage` 对 `from/to` 使用同一半开区间，通过事件所属服务过滤 environment，并分别实现 total、unresolved、responded、recovered 和 affected-services 样本语义；`returnTo` 可恢复原始分析筛选与 `failedService` 状态。

变更失败率没有事件列表链接；失败变更表和 `failedService` 页内状态承载专用结果，服务名称仍可进入服务详情。这避免了空 `change=` 造成的伪筛选，同时保持变更实体没有独立工作区的边界。

## 上一周期、delta、排行与导出共源

当前窗口的长度用于构造紧邻的上一窗口，两周期复用相同筛选函数。计数类指标直接相减，时间均值和失败率在两侧都有可比值时生成 delta；失败 change 按 `serviceId` 计数后排序。`buildAnalyticsExport` 接收完整派生对象并输出窗口、前期窗口、当前/前期指标、delta、趋势、排行、失败变更和事件 ID，避免页面与导出重复计算。

## 持久通知偏好与看板 canonical URL

个人偏好开关由 `draft.notifications` 控制，保存成功后整体写入持久 `preferences`；Sidebar 订阅同一 store，以 note/rail label 呈现状态。设置文案把它限定为 Shell 内模拟的后台领域通知与摘要，规则页和 Webhook 仍声明不做真实发送，Toast 调用路径不读取该开关。

看板先把原始 `scope` 和 `column` 映射到允许枚举，再在非法值或显式默认值出现时 replace 搜索参数。筛选内容使用规范化 scope，移动列内容使用规范化 column；清除操作同时移除 scope、column 和其余筛选。单测覆盖非法/default 参数与清除，E2E 覆盖分享 URL 刷新后的控件值及三视口恢复。

## 验证覆盖与剩余缺口

Vitest 覆盖等长上一周期、计数 delta、失败服务排行、导出对象、集中 query、事件列表时间/environment/metric 过滤、通知保存和看板 canonicalize；Playwright 覆盖组合分析钻取、返回来源、通知持久化与 Toast、看板非法 URL、刷新和清除。编排上下文报告 `pnpm build`、`pnpm lint`、`pnpm test`（24/24）及 `pnpm test:e2e`（62 passed / 7 viewport skips）均通过，本次静态复审另执行了 staged/unstaged `git diff --check`。Not tested: 当前套件没有构造“只有成功变更且没有事件”的分析窗口，因此没有捕获上述空态门禁问题。
