# Workbench Shell v3 的多页面协作实现与契约缺口

该新增应用实现了真实路由、共享领域 store 和多类写操作，不是单纯静态视觉稿；事件创建后，列表、看板、详情、收件箱和服务统计共享同一份会话状态。主题 token、`100svh` 根壳、48px PageHeader/Toolbar、内部滚动和三视口测试也已落地，build、lint、Vitest 与 Playwright 全部通过。但若干验收关键能力仍是未消费的 URL、无效果动作、静态分析数据或通用状态开关，自动化结果高估了完整度，当前不能按需求与模板契约交付。

Watch for: **[P1][confirmed]** 工作区切换不切换数据上下文；**[P1][confirmed]** 搜索深链、详情返回与偏好不能恢复/驱动真实状态；**[P1][confirmed]** 看板失败回滚污染时间线且测试未执行拖放；**[P1][confirmed]** Modal/移动抽屉缺少焦点约束；**[P1][confirmed]** 分析时间范围和趋势图仍是静态展示。

**Verdict**: NEEDS_CHANGES

**P0**：无。

## High-level view

**[confirmed]** 领域实体集中在单个 Zustand store，能够支持事件创建、状态、评论、服务和班次的跨页同步；但 `workspaceId` 只存在于 UI store，领域实体没有工作区归属，切换器只改变文字。

**[confirmed]** 主要路由和 URL 筛选已经存在，但恢复链路未闭环：成员/变更搜索结果生成无人消费的参数，详情返回丢失集合筛选，保存的默认首页、快捷键开关和默认事件状态也没有接入消费者。

**[confirmed]** 看板乐观更新的失败补偿复用正常迁移动作，会留下虚假时间线和可能错误的 `resolvedAt`；分析页则用静态趋势和常量指标响应时间范围。现有 E2E 没有触发这些风险路径。

**[confirmed]** 模板 token 和四层表面基本落地，但 1024–1279px 自动图标栏、容器查询、真实导航进度和页面形状骨架缺失。Modal/移动抽屉允许焦点进入背景，键盘与辅助技术门禁未通过。

<details><summary>Details</summary>

## 工作区选择器没有切换业务上下文

**[P1][confirmed]** `workspaceId` 只由 `app-store.ts:5-35` 保存，侧栏在 `sidebar.tsx:16-25` 调用 `setWorkspace` 后没有触发领域数据刷新或筛选。`domain-store.ts:9-40` 维护一套全局实体，`types.ts:5-25` 的实体也没有 `workspaceId`。浏览器从“核心平台”切到“交付工程”后，收件箱仍为相同 10 行且首行内容完全相同。应给领域实体建立工作区归属，并让所有查询/写操作以当前工作区为边界。

## 搜索深链和详情返回没有形成可恢复导航

**[P1][confirmed]** `global-overlays.tsx:41-42` 把成员导航到 `?tab=members&entity=...`、把变更导航到 `?change=...`，但成员面板没有读取 `entity`，`incident-list-page.tsx:17-18` 也没有读取 `change`；实测两个 URL 都没有详情或高亮。事件详情在 `incident-detail-page.tsx:34-35` 又把返回目标固定为 `/incidents` 或 `/incidents/board`，从 `?q=支付&status=investigating` 进入再返回后变成裸 `/incidents`。应让目标消费深链参数，并携带完整来源 URL 或可恢复的路由状态。

## 收件箱“转为事件”没有任何领域效果

**[P1][confirmed]** `inbox-page.tsx:18-21` 对“加入事件/转为事件”展示成功 toast，但 `domain-store.ts:56` 的 `bulkInbox` 只处理 read、close 和 assign；`incident` 分支不创建/关联事件，也不改变事项状态。应定义转换结果，同步事件、收件箱和统计后再反馈成功。

## 事件“删除”实际执行归档

**[P1][confirmed]** `incident-list-page.tsx:16-24` 把“删除”与“归档”都交给 `bulkStatus('archived')`。需求将两者列为独立批量动作；应实现明确的软删除/移除结果，或取消“删除”声明并取得范围确认。

## 看板失败补偿会制造虚假审计记录

**[P1][confirmed]** `incident-board-page.tsx:28-30` 先调用 `setIncidentStatus`，失败时再调用同一 action 恢复；`domain-store.ts:52` 的每次调用都会写时间线，并在目标为 resolved 时设置 `resolvedAt`。失败移动会产生两条未真实发生的状态变化，移到已解决后失败还可能残留解决时间。失败开关依赖标题包含 `FAIL`，但该标题在创建阶段就会失败，UI 无法构造回滚卡片；`incident-board-page.tsx:18` 也没有分派、标签、复制编号和归档菜单。应使用无副作用快照恢复或专用 rollback，并提供可触发失败入口和完整菜单。

## 交付分析的时间维度和趋势图仍是静态展示

**[P1][confirmed]** `analytics-page.tsx:12` 固定七天趋势；`analytics-page.tsx:15-16` 虽读取 `range/from/to`，过滤只使用团队、服务、环境和严重等级；多项指标及周期比较在 `analytics-page.tsx:20` 固定。实测从 7 天切到本季度后“事件总数”仍为 12，趋势/排行不变，`<Legend />` 也未接入序列开关。应让指标、图表、图例与钻取共享同一时间过滤模型。

## 设置值被保存但没有控制应用行为

**[P1][confirmed]** `settings-panels.tsx:50-52` 保存默认首页和快捷键开关，但 `App.tsx:12` 始终跳到 `/inbox`，`global-overlays.tsx:53-56` 始终注册快捷键；实测关闭快捷键后按 `C` 仍打开创建事件。`defaultStatus` 可在 `settings-panels.tsx:20-22` 修改，创建表单却固定为 triage。成员、团队、规则和集成在 `settings-panels.tsx:26-48` 还绕过统一 `useSaving`，缺少保存中、失败保留、取消、未保存提醒，团队停用也未确认。应把设置接入消费者并统一 mutation/dirty/confirm 契约。

## SPA 内导航会直接丢弃未提交草稿

**[P1][confirmed]** `use-unsaved-warning.ts:3-8` 只监听 `beforeunload`，React Router 的侧栏、面包屑和页签跳转不会触发卸载。评论、事件字段和设置草稿可无确认丢失。应拦截应用内导航并显示确认对话框，同时保留刷新/关闭标签页保护。

## Modal 与移动导航没有焦点隔离

**[P1][confirmed]** `primitives.tsx:26-32` 只设置初始焦点和关闭后返回，未实现 Tab 循环或背景 inert；浏览器连续 Tab 已确认焦点会离开 `role=dialog`。`sidebar.tsx:52` 的移动抽屉也没有 dialog 语义、焦点进入/约束、Esc 关闭和焦点返回。应采用具备焦点管理的 Dialog/Sheet primitive。

## 1024–1279px 壳层和容器响应不符合模板

**[P1][confirmed]** `index.css:89-92` 只有 `<1024px` 和 `>=1280px` 断点，`sidebar.tsx:51` 的折叠完全取决于持久状态；1100px 实测侧栏仍为 256px，而模板要求 48px 图标栏。卡片/指标列全部使用 viewport media query，项目没有 `@container`。应补齐 compact 壳状态，并让内部列结构由容器宽度驱动。

## 页面状态反馈没有复制各页面最终结构

**[P2][confirmed]** `primitives.tsx:41-50` 用同一个“表头 + 六条行”骨架覆盖所有 `PageStateGate`，看板、卡片、日历、设置和分析 loading 都不是最终结构副本；`app-shell.tsx:12` 的 2px 导航进度始终透明。`?state=loading` 还是永久状态，无法验证加载到成功/失败的转换。应按页面模式实现骨架，并让 mock 请求和导航进度经历可观察生命周期。

## 核心需求矩阵仍有未实现项

**[P1][confirmed]** `inbox-page.tsx:15-21` 缺来源、负责人和时间范围筛选；`incident-list-page.tsx:17-24` 缺创建人和时间范围，负责人也不是实体详情链接；值班详情不能查看负责期间事件；评论 `@` 没有成员选择；附件没有可见进度和原文件重试；看板没有快捷菜单。这些都是提示词明确要求的交互，应按 route inventory 建立逐项验收矩阵。

## 27 个 E2E 没有覆盖其标题暗示的风险路径

**[P1][confirmed]** `e2e/smoke.spec.ts:27-35` 的看板用例点击“下一状态”，未执行 dnd-kit 拖放、失败或回滚；`e2e/smoke.spec.ts:63-75` 的空/错态只打开通用 `?state=`。三项目只是重复同 9 个 smoke，compact 取 900px，没有覆盖 1024–1279px 图标栏，也未覆盖工作区、历史前后退、深链、筛选返回、焦点约束、设置失败/取消、图表范围变化和各主要页面状态。应保留 smoke，并增加针对这些行为的结果断言。
