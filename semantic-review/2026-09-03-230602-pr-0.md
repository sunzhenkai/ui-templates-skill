# 工作台语义 P1 修复复审

本次新增的 `web-v3` 已建立工作区作用域 selector、成功后提交的看板迁移、数据派生分析、Router blocker 与 URL canonical 化。实现以 Zustand 领域仓库集中 mutation，页面通过 `useWorkspaceDomainStore` 消费当前工作区数据。仍有 6 类 P1 行为缺口及相应测试盲区；未发现 P0。

Watch for: **confirmed** — mutation 层仍能写入其他工作区的关联 ID；**confirmed** — 多个真实 modal 草稿在 SPA 导航时会直接丢失；**confirmed** — 通知规则提供可操作但不生效的假能力；**confirmed** — 批量收件箱转换可部分提交；**confirmed** — 分析的变更失败率与团队/环境筛选不一致；**confirmed** — 若干跨实体链接丢失来源。

**Verdict**: NEEDS_CHANGES

## High-level view

**confirmed** — 工作区读取路径已统一过滤，但写路径没有封闭关联完整性。`updateIncident`、`updateMember`、`saveTeam` 未验证关联 ID，`saveShift` 只要求值班人和交接人中任意一个有效，领域层仍可形成跨工作区外键。

**confirmed** — 收件箱单项转换会原子创建事件并回写关联，批量入口却逐项立即提交。后续项失败不会回滚前面的转换，错误 toast 与实际部分成功状态不一致。

**confirmed** — 分析大部分结果来自当前筛选数据，但变更失败率只应用时间与服务条件。团队或环境筛选会收窄其他指标，却不会收窄该指标的变更集合。

**confirmed** — 浏览器通知偏好已禁用并说明不可用，通知规则页仍允许创建、启停、编辑和删除没有投递路径的规则，形成会“生效”的配置假象。

**confirmed** — 分页 canonical、`team`/`change` 筛选和主要 returnTo 已实现；全局搜索成员/变更、服务依赖和相似事件跳转仍丢失当前来源。

**confirmed** — 事件详情和设置面板使用 blocker，创建事件 modal 也注册 SPA 阻断；服务、班次及设置中的多个表单只防关闭或完全没有 dirty guard，侧栏导航会无提示销毁草稿。

## mutation 层未封闭工作区关联完整性

**confirmed** — `src/stores/domain-store.ts:55` 的 `updateIncident` 只校验目标事件属于当前工作区，直接合并 `serviceId`、`assigneeId`、`teamIds` 和 `changeIds`；调用方可以把另一个工作区的 ID 写进当前事件。`updateMember` 的 `teamId` 和 `saveTeam` 的 `memberIds`/`serviceIds` 也没有归属校验。`src/stores/domain-store.ts:73` 的 `saveShift` 使用单个 `some(memberId || handoffId)`，只要两名成员中有一个属于当前工作区就会通过。

selector 只能隐藏外部实体，不能修复已写入的外键；这些关联随后会显示成“未分派/未知”并污染统计和编辑。所有关系 mutation 应在提交前验证当前工作区，失败时保持状态不变。

## 批量收件箱转换可产生部分成功

**confirmed** — `src/pages/inbox/inbox-page.tsx:20` 执行 `ids.map(convertInboxToIncident)`，每次调用都会立即提交。若前一项成功、后一项因悬空关联或缺少关联数据失败，已创建事件和 inbox 关联不会回滚，页面却只显示失败。

`src/test/smoke.test.tsx:32` 只覆盖单项重复调用。批量入口需要整批预检后一次提交，才能满足原子转换契约。

## modal 草稿只防关闭、不防 SPA 导航

**confirmed** — `ServiceForm` 和 `ShiftForm` 只向 `Modal` 传入 `dirty`，没有调用 `useUnsavedWarning`；X、遮罩、Esc 会确认，但侧栏 `NavLink` 会直接卸载页面。邀请成员、团队、通知规则和集成表单甚至未传 `dirty`，关闭和导航都能直接丢失输入。

`src/test/smoke.test.tsx:93` 只调用 `requestGuardedClose` helper，未操作任何真实 modal。每个有草稿的 modal 都需要统一 blocker，并通过实际遮罩、Esc、按钮和 SPA 导航验证保留/放弃行为。

## 通知规则是无投递能力的可操作假配置

**confirmed** — `src/pages/settings/settings-panels.tsx:40-43` 暴露通知规则创建、编辑、启停和删除，文案表达规则会按触发条件通知；实现没有规则触发、渠道投递或站内通知消费路径。个人偏好的禁用说明不能消除规则页的行为承诺。

在通知能力实现前，应把规则区域改为明确说明且不可操作；或者补齐规则匹配和可观察的通知结果。

## 变更失败率忽略团队和环境筛选

**confirmed** — `src/lib/analytics.ts:29` 的 `relevantChanges` 只检查时间窗口和 `filters.service`，事件集合还应用 `team`、`environment` 和 `severity`。选择支付团队后，趋势和总数只含支付事件，变更失败率仍会混入平台 SRE 服务的变更；环境筛选同样失真。

变更可通过 `serviceId` 关联服务和团队，至少 team/environment 应同步过滤。severity 无法直接映射时应明确指标定义，而不是静默使用全量变更。

## 跨实体跳转未一致保留来源

**confirmed** — `src/components/app-shell/global-overlays.tsx:45-46` 的成员和变更搜索结果直接跳转，不携带 returnTo。`src/pages/services/services-page.tsx:36` 的依赖服务链接也直接跳转；事件详情的相似事件把 returnTo 设为原始列表，而非当前详情，因此下一详情不能返回来源详情。

这些路径应与已使用 `withReturnTo` 的列表、看板和分析链接统一，目标页也要消费返回来源。

## 回归门禁未覆盖剩余契约

**confirmed** — 12 个 Vitest 用例未尝试跨工作区外键写入、批量转换中途失败、真实 modal 的 SPA 离开、通知控件真实性、团队/环境下的变更失败率或跨实体返回链路。新增 E2E 只覆盖四条浏览器路径，且按要求未运行，因此这些缺口不会使当前门禁失败。
